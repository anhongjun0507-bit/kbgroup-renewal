# 회원가입 표시 이름 필수화 (2026-11-12 원문)

[목표]
KB개발 사이트(kbgroup.kr) 회원가입 폼의 "표시 이름 (선택)" 필드를 필수 입력으로 바꾸고, 관리자 승인 기준 안내 문구를 넣는다.
지금 만드는 것: 관리소장·단지 관계자가 가입하면 관리자가 승인하는 회원제 게시판. 관리자가 가입자를 단지 단위로 식별할 수 있어야 승인 판단이 가능하다.

명세 원문은 docs/specs/signup-display-name-required.md 에 저장하고, 코드와 다른 점부터 보고한 뒤 시작해.
먼저 확인할 것:
- 표시 이름이 저장되는 컬럼(profiles.display_name 등)과 기존 회원 중 비어 있는 행 수
- 표시 이름을 수정할 수 있는 다른 화면(마이페이지 등)이 있는지
- 관리자 회원 승인 화면에 표시 이름이 보이는지

[변경]
- 라벨: "표시 이름 (선택)" → "이름(단지명)"
- 필수 표시는 기존 필수 필드(이메일·비밀번호)와 같은 방식
- 필드 아래 안내 문구: "이름(단지명) 형식으로 입력해야 관리자 승인이 진행됩니다."
- placeholder: "예) 홍길동(OO아파트)"
- 검증: 클라이언트와 서버 액션 양쪽에서 공백만 입력·빈 값 차단. 앞뒤 공백 제거 후 저장. 최대 길이는 기존 제한이 있으면 그대로, 없으면 30자
- 빈 값 제출 시 에러 문구: "이름(단지명)을 입력해 주세요."
- 형식(괄호 포함 여부)은 강제하지 않는다. 판단은 관리자 승인 단계에서 한다. 형식 강제는 정상 가입자를 막을 수 있다
- 마이페이지에서 표시 이름을 비울 수 있다면 같은 필수 검증을 적용한다. 라벨·문구는 동일하게
- 관리자 회원 승인 목록에 표시 이름이 안 보이면 보이게 한다(승인 판단에 필요한 최소 변경)

[범위 밖]
- DB 컬럼에 NOT NULL 제약을 걸지 않는다. 기존 회원 중 빈 값이 있으면 제약이 깨진다. 검증은 앱 레벨로만
- 기존 회원 데이터는 수정하지 않는다. 빈 값 회원 수만 보고
- 로그인·비밀번호 찾기·이메일 인증 흐름은 손대지 않는다
- 범위 밖 리팩터·새 파일 만들지 않는다. 검증용 테스트 계정은 끝에 삭제

[합격 기준]
- 빈 값·공백만 입력 시 가입 차단 + 에러 문구 표시 — 캡처
- 정상 입력 시 가입 성공, DB에 앞뒤 공백 제거된 값 저장 — 조회 결과로 증명
- 서버 액션을 직접 호출해도 빈 값 차단 — 실행 출력으로 증명
- 데스크탑 1440·모바일 390에서 라벨·안내 문구·placeholder 확인 — 캡처 2장
- 관리자 승인 목록에 표시 이름 노출 — 캡처
- tsc·eslint 신규 0건, 빌드 EXIT=0, 라우트 표 무변화
- 회원가입 외 페이지 SSR 가시 텍스트 diff 0줄
- 프로덕션 배포 후 라이브에서 위 차단·성공 2건 재확인(로컬 통과만으로 PASS 처리하지 않는다)

[자율도]
질문 없이 끝까지. 배포는 docs/DEPLOY.md 절차대로(토큰은 환경변수로만). 검증 통과 못 하면 배포하지 말고 보고. 같은 문제를 두 번 고쳐도 안 되면 더 고치지 말고 보고.
